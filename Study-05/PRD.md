## 0. 현재 코드베이스 상태 (사실 확인)

- `Study-05/` 폴더에는 이번 작업과 무관한 기존 산출물이 이미 존재한다: `index.html`("오늘의 마음 - AI 공감 다이어리", 감정 분석/공감 메시지 앱, 클라이언트에서 직접 OpenRouter를 호출하는 구조, 모델 `nex-agi/nex-n2.5-pro:free` 사용).
  - 이 문서(PDF 요약 도우미)는 **별도의 신규 기능**이다. `index.html`을 재사용/수정하지 않으며, 새 파일 `index_pdf.html`과 백엔드 서버 코드를 신규로 추가한다.
  - 단, `index.html`의 OpenRouter 호출/에러 처리 패턴과 사용된 무료 모델은 참고 자료로 유효하다 (아래 6장 참고).
- `.env`(git 미추적)에는 `OPENROUTER_API_KEY` 하나만 정의되어 있다.
- 백엔드 서버, package.json, PDF 처리 라이브러리 등은 아직 전혀 존재하지 않는다 — 전부 이번 파이프라인에서 신규 구현 대상이다.

## 1. 배경 및 목표

### 배경
사용자가 긴 PDF 문서를 매번 직접 읽지 않고, AI에게 업로드해 핵심 내용을 빠르게 파악하고 싶어한다. Study-05는 OpenRouter API 키를 이미 보유하고 있어 이를 활용한 개인 학습용 도구를 만든다.

### 목표
- PDF를 업로드하면 텍스트를 추출하고, OpenRouter의 무료 LLM으로 요약을 생성해 화면에 보여주는 로컬 실행형 웹 도구를 만든다.
- API 키는 반드시 서버 측에만 존재해야 하며, 브라우저/클라이언트 코드에 노출되지 않는다.
- 최종 산출물: `index_pdf.html`(프론트엔드, 더블클릭으로 열람 가능) + 로컬 백엔드 서버(Node.js, 별도 실행 필요).

### 타겟 사용자
- 프로젝트 소유자 본인(개인 학습용, 1인 사용). 로그인/멀티유저/배포 개념 없음. 로컬 PC에서만 실행.

## 2. 사용자 요구사항 (시나리오)

1. **정상 흐름**: 사용자가 로컬 서버를 실행한 뒤 `index_pdf.html`을 더블클릭으로 연다. 화면의 드래그&드롭 영역에 PDF 파일을 끌어다 놓거나 클릭해서 파일을 선택한다. 업로드가 시작되면 로딩 상태가 표시되고, 완료되면 한국어로 된 요약 결과가 화면에 나타난다.
2. **서버 미실행**: 사용자가 서버를 켜지 않고 `index_pdf.html`만 열었다면, 업로드 시도 시 "서버에 연결할 수 없습니다. 로컬 서버를 먼저 실행해주세요." 같은 명확한 한국어 에러 메시지를 본다.
3. **잘못된 파일**: 사용자가 PDF가 아닌 파일(예: .png, .docx)을 올리면 즉시(서버 요청 전, 클라이언트 단에서) 에러 메시지를 본다.
4. **너무 큰 파일**: 파일 크기 제한을 초과하면 업로드 전 또는 서버 응답에서 명확한 에러 메시지를 본다.
5. **텍스트 추출 실패**: 스캔 이미지로만 된 PDF(텍스트 레이어 없음) 등 텍스트 추출이 불가능한 경우, "이 PDF에서는 텍스트를 추출할 수 없습니다(이미지 스캔본일 수 있음)" 같은 메시지를 본다.
6. **AI 호출 실패**: OpenRouter 요청이 실패(네트워크 오류, 요청 한도 초과, 서버 오류 등)하면 원인을 짐작할 수 있는 한국어 메시지를 보고, 재시도할 수 있다.
7. **긴 문서**: 텍스트가 매우 길어 모델 컨텍스트/처리 시간에 부담이 되는 경우, 서버가 텍스트를 안전한 길이로 잘라 요약하고 "문서가 길어 일부만 요약했습니다" 같은 안내를 함께 보여준다 (전체 청크 분할 요약은 Out of scope, 3.2 참고).

## 3. 기능 범위

### 3.1 In scope (MVP)
- PDF 파일 업로드 (드래그&드롭 + 클릭하여 파일 선택)
- 서버에서 PDF 텍스트 추출 (텍스트 레이어가 있는 PDF 대상)
- 추출 텍스트를 OpenRouter 무료 모델로 요약 (한국어 요약 결과)
- 요약 결과를 화면에 깔끔하게 표시 (한국어 UI)
- 업로드 제약(크기/확장자) 검증 및 사용자 친화적 에러 메시지
- 업로드/추출/요약 각 단계의 로딩 상태 표시
- 텍스트가 너무 길 경우 자동 truncation + 안내 문구

### 3.2 Out of scope (이번 버전에서 하지 않음)
- 회원가입/로그인/인증, 다중 사용자 지원
- 요약 결과의 서버측 영구 저장(DB). 필요 시 브라우저 `localStorage`로 이력 표시하는 정도까지만 고려 가능하나 MVP 필수 아님 (구현 여부는 frontend-developer 재량, 필요 시 PM과 확인)
- 다중 PDF 동시 업로드, 배치 처리
- 매우 긴 문서에 대한 청크 분할 + 재귀 요약(map-reduce summarization) — MVP는 truncation으로 대응
- 스캔 이미지 PDF에 대한 OCR
- 요약 스타일 커스터마이징(길이/톤 선택 UI), 다국어 원문 대응 품질 보장
- 배포/호스팅, HTTPS, 클라우드 인프라 — 로컬 실행 전용
- 유료 OpenRouter 모델 사용, 모델 자동 전환/폴백 로직의 정교한 재시도 정책 (단순 실패 알림 수준까지만)
- PDF 다운로드/내보내기, 요약 결과 공유 기능

## 4. 핵심 기능 명세

### 4.1 업로드 제약사항
| 항목 | 값 | 근거 |
|---|---|---|
| 허용 확장자/MIME | `.pdf` / `application/pdf` | 요구사항상 PDF 전용 |
| 최대 파일 크기 | 10MB | 무료 모델 컨텍스트와 로컬 처리 성능을 고려한 실용적 상한. 이후 필요 시 조정 가능 (오픈 이슈 참고) |
| 동시 파일 수 | 1개 | MVP 범위 (3.2 참고) |
| 클라이언트 사전 검증 | 확장자/MIME, 크기를 프론트엔드에서 먼저 확인해 불필요한 업로드 방지 | UX 개선 |
| 서버 측 검증 | 클라이언트 검증과 무관하게 서버에서 동일 기준으로 재검증 (필수) | 클라이언트 검증은 우회 가능하므로 서버가 최종 방어선 |

### 4.2 텍스트 추출
- 텍스트 레이어가 있는 PDF에서 순서대로 텍스트를 추출한다.
- 추출된 텍스트가 비어있거나 공백만 있을 경우(예: 이미지 스캔본) → `EXTRACTION_EMPTY` 에러로 처리.
- 추출 텍스트 길이 상한(제안): 약 60,000자(공백 포함). 이를 초과하면 앞부분부터 60,000자까지만 사용하고, 응답에 `truncated: true` 플래그를 포함해 프론트가 안내 문구를 표시하게 한다.
  - 근거: 아래 6장에서 선정하는 무료 모델은 컨텍스트가 넉넉하지만(최소 6.5만 토큰 이상), 무료 모델의 응답 지연/요청당 처리 비용을 고려해 안전한 상한을 둔다. 정확한 상한값은 ai-integration-specialist가 실제 모델 테스트 후 조정 가능.

### 4.3 AI 요약
- 추출된 텍스트를 시스템 프롬프트와 함께 OpenRouter Chat Completions API에 전달한다.
- 요약은 한국어로 생성한다 (원문이 영어 등 다른 언어여도 요약 결과는 한국어).
- 요약 형식(제안, ai-integration-specialist가 프롬프트 설계 시 확정): 3~6문장 또는 3~5개 핵심 불릿 포인트. 정확한 형식은 프롬프트 엔지니어링 단계에서 결정.
- 요청 타임아웃: 60초 (무료 모델은 응답이 10~40초 이상 걸릴 수 있음, 기존 `index.html`의 45초 타임아웃 사례 참고).

## 5. API 명세 (백엔드)

베이스 URL: `http://localhost:<PORT>` (PORT 기본값 제안: 3000, backend-developer가 확정)

### 5.1 `POST /api/summarize`
PDF 업로드 → 텍스트 추출 → AI 요약까지 한 번에 처리하는 단일 엔드포인트 (MVP 단순화를 위해 업로드/추출/요약을 분리하지 않음).

**요청**
- `Content-Type: multipart/form-data`
- 필드명: `pdf` (파일 1개, PDF)

**성공 응답 (200)**
```json
{
  "success": true,
  "data": {
    "fileName": "example.pdf",
    "fileSizeBytes": 1048576,
    "pageCount": 12,
    "extractedTextLength": 15320,
    "truncated": false,
    "summary": "이 문서는 ...",
    "model": "google/gemma-4-31b-it:free",
    "tookMs": 8342
  }
}
```

**실패 응답 (4xx/5xx, 공통 포맷)**
```json
{
  "success": false,
  "error": {
    "code": "FILE_TOO_LARGE",
    "message": "파일 크기는 10MB를 초과할 수 없습니다."
  }
}
```

**에러 코드 정의**
| code | HTTP status | 상황 |
|---|---|---|
| `NO_FILE` | 400 | 파일이 첨부되지 않음 |
| `INVALID_FILE_TYPE` | 400 | PDF가 아닌 파일 |
| `FILE_TOO_LARGE` | 413 | 10MB 초과 |
| `EXTRACTION_FAILED` | 422 | PDF 파싱 자체가 실패(손상된 파일 등) |
| `EXTRACTION_EMPTY` | 422 | 추출된 텍스트가 없음(이미지 스캔본 등) |
| `OPENROUTER_AUTH_ERROR` | 502 | API 키 오류(서버 설정 문제, 사용자에게는 일반 메시지로 노출) |
| `OPENROUTER_RATE_LIMITED` | 429 | 무료 모델 요청 한도 초과 |
| `OPENROUTER_TIMEOUT` | 504 | AI 응답 시간 초과 |
| `OPENROUTER_ERROR` | 502 | 그 외 OpenRouter 오류 |
| `INTERNAL_ERROR` | 500 | 그 외 서버 오류 |

### 5.2 `GET /api/health`
서버가 켜져 있는지 프론트엔드가 확인하기 위한 헬스체크 (시나리오 2 대응).

**응답 (200)**
```json
{ "status": "ok" }
```

## 6. OpenRouter 무료 모델 선정

**조건: 반드시 무료(요청당 비용 $0) 모델만 사용한다.** 아래는 2026-09-10 기준 `openrouter.ai/models`(무료 필터)에서 확인한 실제 존재하는 무료 모델 목록 중 요약 작업에 적합한 후보다. 무료 모델 목록은 OpenRouter 측 사정으로 수시로 바뀌므로, ai-integration-specialist는 실제 구현 시점에 `openrouter.ai/models?max_price=0` 또는 `GET https://openrouter.ai/api/v1/models`로 재확인 후 최종 확정할 것.

| 우선순위 | 모델 ID | 제공사 | 컨텍스트 | 비고 |
|---|---|---|---|---|
| 1순위(권장) | `google/gemma-4-31b-it:free` | Google | 262K | 잘 알려진 제공사, instruction-tuned, 일반 텍스트 요약에 안정적일 것으로 기대 |
| 2순위(폴백) | `nex-agi/nex-n2.5-pro:free` | Nex AGI | 262K | 이 저장소의 기존 `index.html`(AI 공감 다이어리)에서 이미 사용 중 — JSON 강제 출력 등 실제 동작이 검증된 전례가 있어 폴백으로 신뢰도 있음 |
| 참고(대형) | `nvidia/nemotron-3-super-120b-a12b:free` | NVIDIA | 262K | 파라미터 규모가 커서 품질이 더 나을 가능성, 응답 지연이 더 길 수 있음 |

**결정 방식**: ai-integration-specialist가 1순위 모델로 실제 PDF 텍스트 요약을 테스트하고, 품질/속도가 부족하면 2순위로 교체한다. 본인 에이전트 지침대로 실제 호출 결과를 확인한 뒤 최종 모델을 코드에 반영하고, 변경 시 이 PRD의 표를 갱신한다.

**공통 요청 파라미터 가이드** (세부 값은 ai-integration-specialist 재량):
- `temperature`: 낮은 값(0.3~0.5) 권장 — 요약은 창의성보다 사실 충실도가 중요
- 타임아웃: 60초 (4.3 참고)
- 요청 헤더에 `HTTP-Referer`, `X-Title` 포함 (OpenRouter 권장 관례, 기존 `index.html` 참고)

## 7. UI/UX 요구사항

- **언어**: 전체 인터페이스 한국어. 에러 메시지도 한국어로, 사용자가 다음 행동을 알 수 있도록 구체적으로 작성.
- **업로드 영역**: 드래그&드롭 지원 + 클릭 시 파일 선택 다이얼로그. 드래그 중(hover) 시각적 피드백(테두리/배경색 변화) 제공.
- **상태 표시**:
  - 대기 상태(초기 화면): 업로드 안내 문구
  - 업로드/처리 중: 스피너 + "PDF에서 텍스트를 추출하고 있어요..." → "AI가 요약을 작성하고 있어요..." 등 단계별 문구(서버가 단계 정보를 안 주면 단일 문구로 통합 가능, frontend-developer 재량)
  - 완료: 요약 결과 카드. 파일명, 페이지 수, (truncated인 경우) "문서가 길어 일부만 요약했습니다" 안내 포함
  - 에러: 에러 카드에 명확한 한국어 메시지 + 재시도 버튼
- **접근성**: 시맨틱 마크업, 키보드로 파일 선택 가능(드래그&드롭 대체 수단 필수), 충분한 색상 대비, `aria-live` 등으로 상태 변화 스크린리더 알림 (기존 `index.html`의 패턴 참고 가능).
- **반응형**: 모바일~데스크톱 대응 필요 없음(로컬 개인 PC 사용 전제)이지만, 최소한 일반적인 데스크톱 브라우저 창 크기에서 깨지지 않아야 함. 모바일 대응은 선택사항(과도한 투자 금지).
- **서버 미연결 안내**: 페이지 로드 시 또는 최초 업로드 시도 시 `/api/health`로 서버 연결을 확인하고, 실패 시 "로컬 서버를 먼저 실행해주세요" 안내를 표시 (실행 방법은 별도 README에서 안내, 이 화면에서는 짧은 안내만).

## 8. 비기능 요구사항

### 8.1 보안
- `OPENROUTER_API_KEY`는 서버(`.env`)에만 존재해야 하며, 어떤 경우에도 프론트엔드 코드, API 응답, 로그, 커밋에 노출되지 않는다.
- 서버는 업로드된 파일을 처리 후 즉시 폐기(디스크에 영구 저장하지 않거나, 처리 후 삭제)한다. 개인 문서가 포함될 수 있으므로 불필요한 보관을 하지 않는다.
- 파일 업로드는 서버 측에서 MIME 타입과 크기를 반드시 재검증한다 (클라이언트 검증 우회 가능성 대비).
- CORS: 로컬 단일 사용자 도구이므로 `index_pdf.html`을 여는 origin(`file://` 또는 로컬 정적 서버)에서의 요청만 허용하도록 개발 편의 수준에서 설정하되, 와일드카드 전체 허용은 지양.

### 8.2 성능
- 일반적인 크기(수십 페이지, 수MB) PDF 기준으로 업로드~요약 완료까지 목표 60초 이내 (무료 모델 특성상 지연 가능성이 있으므로 프론트 로딩 UX로 체감 지연을 완화).
- 동시 요청 처리량 최적화는 불필요 (1인 사용, 순차 처리로 충분).

### 8.3 에러 처리
- 모든 실패 지점(파일 검증, PDF 파싱, OpenRouter 호출, 네트워크)에 대해 사용자에게 원인을 유추할 수 있는 한국어 메시지를 반환한다.
- OpenRouter 무료 모델의 요청 한도 초과(429)는 흔히 발생할 수 있으므로 별도 에러 코드(`OPENROUTER_RATE_LIMITED`)로 구분하고, "잠시 후 다시 시도해주세요" 식으로 안내한다.

## 9. 기술 스택 (권장)

- **백엔드**: Node.js + Express
  - PDF 텍스트 추출: `pdf-parse` (경량, 텍스트 레이어 추출에 충분) — 대안 라이브러리가 더 적합하다고 판단되면 backend-developer가 근거와 함께 교체 제안 가능
  - 파일 업로드 처리: `multer` (multipart/form-data, 메모리 스토리지 권장 — 디스크에 남기지 않기 위해, 8.1 참고)
  - `.env` 로드: `dotenv`
  - CORS: `cors` 패키지
- **프론트엔드**: 별도 빌드 도구 없는 순수 HTML/CSS/JS 단일 파일(`index_pdf.html`) — "더블클릭으로 열기" 요구사항과 기존 `index.html` 패턴에 부합. React 등 프레임워크 도입은 이 요구사항 규모에 비해 과함.
- 위 선택이 부적절하다고 판단되면 backend-developer/frontend-developer가 대안을 근거와 함께 제안하고 PM(및 사용자)과 확인 후 변경한다.

## 10. 마일스톤 (파이프라인 순서)

1. **backend-developer**: Express 서버 스캐폴딩, `/api/health`, `/api/summarize`(업로드 검증 + PDF 텍스트 추출까지), `.env` 로드, 에러 응답 포맷 구현. OpenRouter 호출 부분은 자리만 만들어두고(placeholder) 다음 단계로 넘김.
2. **ai-integration-specialist**: OpenRouter 연동 완성 — 6장의 후보 모델 실테스트 후 최종 모델 확정, 요약 프롬프트 설계, 에러/타임아웃 처리, truncation 로직 연동.
3. **frontend-developer**: `index_pdf.html` 구현 — 드래그&드롭 업로드 UI, 상태 전환(대기/로딩/결과/에러), `/api/summarize` 및 `/api/health` 연동, 접근성.
4. **qa-engineer**: 정상 흐름 + 5장에 정의된 모든 에러 케이스(잘못된 파일, 큰 파일, 서버 미실행, 추출 실패, AI 호출 실패, 긴 문서 truncation) 실제 실행 검증.

각 단계는 이전 단계 산출물을 실제로 확인한 뒤 시작한다. 요구사항 해석에 이견이 생기면 이 PRD를 기준으로 하되, 모호한 지점은 PM(사용자)에게 확인한다.

## 11. 오픈 이슈 (확정 필요 시 사용자 확인)

1. 파일 크기 상한(10MB)과 텍스트 truncation 기준(60,000자)은 PM이 실용적으로 제안한 기본값이며, 실제 사용할 PDF 크기에 따라 조정이 필요할 수 있다.
2. 6장의 1순위 모델(`google/gemma-4-31b-it:free`)은 문서 작성 시점 기준 존재가 확인된 무료 모델이나, 실제 요약 품질은 아직 테스트되지 않았다. ai-integration-specialist의 실측 후 최종 확정 필요.
3. 요약 결과를 브라우저에 임시로라도 기록/보관할지(예: `localStorage` 이력 — 기존 `index.html`의 패턴처럼) 여부는 미정. 필요하면 별도 확인 후 범위에 추가.
4. 서버 실행 방법(포트, 실행 명령 등) 안내를 `index_pdf.html` 화면에 넣을지, 별도 README로만 안내할지 미정 — backend-developer 구현 시점에 결정.
