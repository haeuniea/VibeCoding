# PRD: 개인용 할 일 관리 앱 (Personal To-Do App)

## 1. 개요

### 1.1 배경 및 목적
매일 10~20개 수준의 할 일을 관리하는 **개인용** 웹 앱을 만든다. 회원가입, 서버, 별도 설치 과정 없이 브라우저에서 바로 열어서 쓸 수 있는 가벼운 도구를 목표로 한다.

### 1.2 문제 정의
- 무거운 협업 툴(Notion, Todoist 등)은 개인이 하루 단위로 쓰기엔 기능이 과하다.
- 종이 메모나 텍스트 파일은 완료 체크, 카테고리 분류, 진행률 확인이 불편하다.

### 1.3 목표
- 할 일을 빠르게 추가/관리하고, 하루 진행 상황을 한눈에 파악한다.

## 2. 대상 사용자

- 단일 사용자(본인), 로그인/회원가입 불필요
- 데스크톱 브라우저 사용 기준 (모바일 대응은 선택 사항)

## 3. 핵심 기능 요구사항 (Functional Requirements)

| ID | 기능 | 상세 설명 |
|----|------|----------|
| FR-1 | 할 일 추가 | 텍스트 입력 + 카테고리 선택 후 등록. 빈 값은 등록 불가 |
| FR-2 | 할 일 수정 | 기존 항목의 텍스트/카테고리를 인라인 또는 편집 모드로 수정 |
| FR-3 | 할 일 삭제 | 개별 삭제. 실수 방지를 위한 확인(confirm) 절차 권장 |
| FR-4 | 완료 체크 | 체크박스 클릭으로 완료/미완료 토글, 완료 항목은 취소선 등으로 시각적 구분 |
| FR-5 | 카테고리 분류 | 업무 / 개인 / 공부 3종 고정 카테고리, 항목별 색상 또는 태그로 구분 |
| FR-6 | 진행률 보기 | 전체 완료율(%)을 진행률 바 또는 숫자로 표시 |

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **실행 환경**: 브라우저에서 파일을 열거나 정적 호스팅만으로 동작 (서버/백엔드 불필요)
- **데이터 지속성**: 새로고침·브라우저 재시작 후에도 데이터 유지
- **기술 스택**: 순수 HTML/CSS/JavaScript (프레임워크, 빌드 도구 없이 동작)
- **성능**: 항목 20개 내외 기준이므로 별도 최적화 불필요

## 5. 데이터 모델

```
Todo {
  id: string          // 고유 식별자 (예: timestamp 기반)
  title: string        // 할 일 내용
  category: "업무" | "개인" | "공부"
  completed: boolean
  createdAt: number    // 생성 시각
}
```

## 6. 화면 구성 (UI 요구사항)

1. **입력 영역**: 텍스트 입력창 + 카테고리 선택(드롭다운 또는 버튼) + 추가 버튼
2. **목록 영역**: 체크박스, 할 일 텍스트, 카테고리 태그, 수정/삭제 아이콘
3. **필터**: 전체 / 업무 / 개인 / 공부 탭 (선택 사항이지만 있으면 편의성 ↑)
4. **진행률 영역**: 상단 또는 하단에 진행률 바 + "n / 전체 완료" 텍스트

## 7. 기술 설계 방향

### 7.1 데이터 저장 방식 비교

| 방식 | 특징 | 새로고침 유지 |
|------|------|------|
| 변수(메모리)만 사용 | 구현 간단 | ❌ 새로고침 시 소실 |
| sessionStorage | 탭 단위 저장 | ❌ 탭/브라우저 종료 시 소실 |
| **localStorage** | 브라우저에 영구 저장, API 간단 | ✅ 새로고침·재시작 후에도 유지 |
| IndexedDB | 대용량·구조화 데이터에 적합 | ✅ 유지되지만 API가 복잡 |

**권장: localStorage.** 하루 10~20개 수준의 단순 텍스트 데이터에는 IndexedDB의 복잡도가 불필요하며, `localStorage.setItem`/`getItem`으로 충분히 요구사항을 만족한다.

### 7.2 파일 구조 (권장)
```
index.html   // 마크업
style.css    // 스타일
script.js    // 로직 (CRUD, localStorage 연동, 렌더링)
```
파일 3개로 분리하는 구조를 권장한다. 단일 HTML 파일에 모두 넣는 방법도 가능하지만, 이후 유지보수·가독성을 고려하면 분리가 낫다.

### 7.3 상태 관리
별도 라이브러리 없이 **JS 배열 하나(전체 할 일 목록)를 단일 진실 공급원(source of truth)으로 두고, 변경 시마다 localStorage에 저장 + 화면 다시 그리기(re-render)** 하는 방식을 권장한다. 규모가 작아 이 방식으로도 충분하다.

## 8. 범위 외 (Out of Scope, v1 기준)

- 마감일/알림 기능
- 우선순위 설정, 정렬 기능
- 다크 모드
- 다중 기기 동기화(클라우드 저장)
- 데이터 내보내기/가져오기

## 9. 가정 및 확인이 필요한 사항

아래는 요구사항에 명시되지 않아 임의로 가정한 부분이다. 방향이 다르면 알려주시기 바란다.

- **진행률 정의**: "전체 완료율(%)" 기준으로 가정했다. 카테고리별 진행률(업무 80%, 개인 50% 등)도 필요하다면 별도 요청 바란다.
- **데이터 범위**: 로컬 브라우저 저장소에만 저장하고, 다른 기기와의 동기화는 하지 않는 것으로 가정했다.
- **삭제 확인**: 삭제 시 확인창(confirm)을 띄우는 것으로 가정했다. 즉시 삭제를 원하면 제외 가능하다.
