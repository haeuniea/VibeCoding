`questions.js`에 새 문제를 하나 추가하는 7단계 일일 루틴을 실행한다.
각 단계는 실행 직후 스스로 검증하고, 하나라도 실패하면 **그 자리에서
즉시 중단**하고 어느 단계에서 무엇이 왜 실패했는지 보고한다. 뒤 단계는
진행하지 않는다.

대상 지정(선택): ${ARGUMENTS}

- 비어 있으면 3단계에서 자동으로 가장 부족한 카테고리를 고른다.
- `카테고리` 또는 `카테고리 난이도` 형태로 지정하면 3단계의 자동 선택
  대신 지정된 값을 사용한다. `난이도`는 `easy`/`medium`/`hard` 중
  하나여야 하며, 지정된 카테고리가 `questions.js`에 없는 값이면
  기존 category 목록을 보여주고 사용자에게 확인한다.

## 절차

### 1단계 — 파일 구조 읽고 이해하기
`questions.js`를 읽어 배열 구조와 각 문제 객체의 필드(`id`, `category`,
`difficulty`, `question`, `options`, `correctAnswer`, `explanation`)를
파악한다.
- **검증**: 배열이 정상 파싱되고, 최소 1개 이상의 문제가 위 7개 필드를
  모두 갖추고 있는가?
- **실패 시**: 파일을 읽을 수 없거나 구조가 예상과 다르면 즉시 중단하고
  어떤 필드/구조가 다른지 보고한다.

### 2단계 — 현재 문제 개수와 분포 확인
전체 문제 수, id 최솟값·최댓값, category별 개수, category별
difficulty(easy/medium/hard) 분포를 집계한다 (`/quiz-stats`와 동일한
집계).
- **검증**: 집계한 category별 합계가 전체 문제 수와 일치하는가?
- **실패 시**: 합계가 어긋나면(예: category 필드 누락·오타) 중단하고
  어떤 문제(id)가 원인인지 보고한다.

### 3단계 — 카테고리별 부족분 파악
각 category가 목표 문제 수(카테고리당 20문제, 3단계 3.5 항목 기준)
대비 몇 개 부족한지 계산한다. `${ARGUMENTS}`로 카테고리가 지정되지
않았다면, 부족분이 가장 큰 category를 이번에 추가할 대상으로 정한다.
동률이면 현재 문제 수가 가장 적은 category를 우선한다. 난이도는 해당
category 안에서 개수가 가장 적은 difficulty를 선택한다(지정된 경우
지정값 사용).
- **검증**: 대상 category·difficulty가 정확히 하나로 정해졌는가?
- **실패 시**: 모든 category가 이미 목표를 만족하면 중단하고 그 사실을
  보고한다(오류가 아니라 "추가할 필요 없음"으로 보고). `${ARGUMENTS}`로
  지정한 category가 존재하지 않으면 기존 category 목록을 보여주고
  사용자에게 확인한다.

### 4단계 — 새 문제 초안 작성 및 중복 체크
3단계에서 정한 category·difficulty에 맞는 새 문제를 하나 작성한다
(`/quiz-add`와 동일한 필드 구조). 작성 직후, `questions.js`의 기존
모든 문제와 비교해 다음이 겹치지 않는지 확인한다.
- 동일하거나 거의 동일한 `question` 문구
- 동일한 사실을 다른 문구로 묻는 사실상 중복 문제
- **검증**: 기존 문제와 겹치지 않는가?
- **실패 시**: 겹치면 다른 소재로 다시 작성해 재검사한다. 같은
  category·difficulty 안에서 중복되지 않는 새 문제를 도저히 만들 수
  없다면 중단하고 이유를 보고한다(파일은 아직 수정하지 않았으므로
  안전하다).

### 5단계 — 형식 검증 (파일에 쓰기 전)
초안이 다음을 모두 만족하는지 확인한다.
- `id`가 기존 최댓값 + 1인가?
- `options`가 정확히 4개이고 `correctAnswer`가 0~3 중 하나를 가리키는가?
- 이 프로젝트 `CLAUDE.md`의 "퀴즈 문제 교차 검증 가이드라인" 4개 항목
  (정답 유일성 / 최상급 표현 기준 명시 / 시점·범위 명시 / 교차 검증)을
  모두 만족하는가?
- **검증**: 위 조건을 모두 만족하는가?
- **실패 시**: 하나라도 어긋나면 초안을 수정해 다시 검증한다. 만족시킬
  수 없으면 중단하고 이유를 보고한다(이 단계까지는 파일에 아직 쓰지
  않는다).

형식 검증을 통과한 뒤에만 실제로 `questions.js`를 수정한다 — 같은
category 문제들이 모여 있는 위치에 추가하고, 기존 코드 스타일(들여쓰기,
따옴표, 쉼표 위치)을 그대로 따른다.

### 6단계 — 전체 데이터 백업
문제를 추가해 저장한 직후, 수정된 `questions.js` 전체를
`.claude/backups/questions_YYYYMMDD_HHMMSS.js` 경로에 그대로 복사해
스냅샷을 남긴다 (`.claude/backups/` 폴더가 없으면 새로 만든다).
- **검증**: 백업 파일이 실제로 생성됐고, 방금 저장한 `questions.js`와
  내용이 동일한가?
- **실패 시**: 백업 파일 생성에 실패하면 중단하고 원인(예: 권한, 경로
  문제)을 보고한다. 이미 `questions.js`에는 문제가 추가된 상태이므로,
  이 사실도 함께 보고한다.

### 7단계 — 실행 결과 상세 보고
아래 내용을 정리해 보고한다.

## 출력 형식

- 이번에 추가된 문제 전체(id, category, difficulty, question, options,
  correctAnswer, explanation)
- 추가 전/후 전체 문제 수, 대상 category의 추가 전/후 문제 수
- 3단계에서 계산한 카테고리별 부족분 표 (이번에 채운 category는 갱신된
  값으로 표시)
- 생성된 백업 파일 경로
- 각 단계의 통과 여부(✅/❌)를 순서대로 나열 — 중단된 경우 어느 단계에서
  멈췄는지와 그 이유를 명확히 표시

어느 단계에서든 중단되면, 그 지점까지의 결과와 실패 원인만 위 형식에
맞춰 보고하고 이후 단계는 "미실행"으로 표시한다.
