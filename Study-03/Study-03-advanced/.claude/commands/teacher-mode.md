`/teacher-setup`, `/teacher-check`, `/teacher-mock-data`, `/teacher-report`
네 명령의 절차를 순서대로 실행하는 통합 명령이다. 각 단계는 실행 직후
스스로 검증하고, 하나라도 실패하면 **그 자리에서 즉시 중단**하고 어느
단계에서 무엇이 왜 실패했는지 보고한다. 뒤 단계는 진행하지 않는다.

데이터 소스(선택): ${ARGUMENTS}

- 비어 있으면 3단계에서 실제 학생 제출 파일 유무에 따라 자동으로
  실데이터/샘플데모 모드를 정한다.
- 폴더 경로가 지정되면 3단계에서 그 폴더를 실데이터로 간주하고
  샘플 생성을 건너뛴다.

## 절차

### 1단계 — 기반 기능 확인/구현
`.claude/commands/teacher-setup.md`를 읽고 그 절차를 그대로 수행한다.
이미 구현되어 있으면(해당 파일의 1번 절차대로) 건너뛴다.
- **검증**: `index.html`에 `#studentNameInput`·`#exportHistoryBtn`,
  `storage.js`에 `exportHistory`가 모두 존재하는가?
- **실패 시**: 구현 중 오류가 나면 중단하고 어떤 파일에서 무엇이
  실패했는지 보고한다.

### 2단계 — 정합성 점검
`.claude/commands/teacher-check.md`를 읽고 그 절차를 그대로 수행한다.
- **검증**: 모든 점검 항목이 ✅인가?
- **실패 시**: ⚠️가 하나라도 있으면 사용자에게 지금 수정할지 묻는다.
  수정에 동의하지 않으면 리포트 신뢰성에 영향을 줄 수 있으므로 여기서
  중단하고 어떤 항목이 남았는지 보고한다.

### 3단계 — 데이터 소스 확보
`${ARGUMENTS}`가 지정되지 않았다면 `.claude/teacher-data/submissions/`에
유효한 학생 JSON 파일이 있는지 확인한다.
- 있으면 그 폴더를 이번 실행의 데이터 소스로 정한다(실데이터 모드).
- 없으면 `.claude/commands/teacher-mock-data.md`의 절차를 그대로
  수행해 `.claude/teacher-data/samples/`에 학생 5명 분량의 샘플을
  생성하고, 그 폴더를 데이터 소스로 정한다(샘플 데모 모드).
- **검증**: 최종 데이터 소스 폴더에 스키마를 만족하는 학생 JSON이
  1개 이상 있는가?
- **실패 시**: 샘플 생성마저 실패하면 중단하고 원인을 보고한다.

### 4단계 — 비교 리포트 생성
`.claude/commands/teacher-report.md`의 절차를 그대로 수행해, 3단계에서
정한 데이터 소스 폴더를 대상으로 학생 비교 리포트를 만든다. 실데이터
모드와 샘플 데모 모드 여부를 리포트 최상단에 그대로 반영한다.
- **검증**: 학생별 비교표와 반 전체 통계가 모두 생성됐는가?
- **실패 시**: 중단하고 원인을 보고한다(이 시점까지의 결과는 이미
  안전하게 남아 있다 — 파일 손상 위험은 없다).

### 5단계 — 종합 보고

## 출력 형식

- 이번 실행에서 사용한 데이터 소스(실데이터 폴더 경로 또는 "샘플
  데모")를 한 줄로 명시
- 4단계에서 만든 리포트 본문(또는 저장된 경우 저장 경로)
- 각 단계의 통과 여부(✅/❌)를 순서대로 나열 — 중단된 경우 어느
  단계에서 멈췄는지와 이유를 명확히 표시

어느 단계에서든 중단되면, 그 지점까지의 결과와 실패 원인만 위 형식에
맞춰 보고하고 이후 단계는 "미실행"으로 표시한다.
