# PRD - 3단계: 사용자 프로필 및 레시피 저장

## 개요

사용자 프로필(계정)을 만들고, 2단계에서 생성된 레시피 중 마음에 든 것을 저장/조회/삭제할 수 있게 한다.

## 목표

- 사용자를 식별할 수 있는 최소한의 계정 체계를 만든다.
- 사용자가 마음에 든 레시피를 나중에 다시 볼 수 있도록 저장한다.

## 사용자 스토리

- 사용자로서, 계정을 만들어서 내가 저장한 레시피를 나중에 다시 확인하고 싶다.
- 사용자로서, 방금 추천받은 레시피가 마음에 들면 저장해두고 싶다.
- 사용자로서, 저장한 레시피 중 필요 없는 것은 지우고 싶다.

## 범위

**포함**
- 회원가입 / 로그인 (이메일 + 비밀번호 기반의 간단한 인증)
- 로그인한 사용자가 2단계 레시피 결과를 "저장" 버튼으로 보관
- 저장한 레시피 목록 조회 화면
- 저장한 레시피 삭제

**제외**
- 소셜 로그인, 비밀번호 재설정 이메일 발송 등 고급 인증 기능
- 사용자 선호도(알레르기, 비선호 재료 등)를 1·2단계 인식/추천 로직에 반영하는 것 — 이번 단계는 "저장"까지만 다루고, 선호도 반영은 이후 별도 개선 과제로 남긴다.

## 사용자 플로우

1. 사용자가 회원가입 후 로그인한다.
2. 2단계에서 레시피 상세 화면을 보다가 "저장" 버튼을 누른다.
3. 백엔드가 해당 레시피를 현재 로그인한 사용자와 연결해 저장한다.
4. 사용자가 "내가 저장한 레시피" 페이지에서 목록을 확인한다.
5. 목록에서 레시피를 클릭하면 상세 내용(2단계와 동일한 형식)을 다시 볼 수 있다.
6. 필요 없는 레시피는 삭제 버튼으로 제거한다.

## 기능 요구사항

- 회원가입: 이메일, 비밀번호 입력, 비밀번호는 해싱하여 저장한다.
- 로그인: 이메일/비밀번호 검증 후 세션 또는 토큰 발급.
- 로그인하지 않은 상태에서 "저장" 버튼을 누르면 로그인 화면으로 유도한다.
- 저장된 레시피는 2단계 레시피 객체(`title`, `used_ingredients`, `missing_ingredients`, `steps`, `estimated_time_minutes`)를 그대로 보관한다.
- 저장 목록은 최신 저장 순으로 정렬해 보여준다.

## 데이터 모델 (초안)

```
User
- id
- email (unique)
- password_hash
- created_at

SavedRecipe
- id
- user_id (User 참조)
- title
- used_ingredients (배열)
- missing_ingredients (배열)
- steps (배열)
- estimated_time_minutes
- created_at
```

## API 설계 (초안)

```
POST /api/signup        { email, password } -> 201
POST /api/login         { email, password } -> { token }
POST /api/recipes/save  { recipe }          -> 201 { saved_recipe }
GET  /api/recipes/saved                     -> { saved_recipes: [...] }
DELETE /api/recipes/saved/:id               -> 204
```

## 비기능 요구사항

- 비밀번호는 평문으로 저장하지 않는다 (해시 알고리즘 사용).
- 인증 토큰/세션은 서버에서만 검증하며, 다른 사용자의 저장 레시피에 접근할 수 없어야 한다 (본인 소유 데이터만 조회/삭제 가능).
- `.env`의 `OPENROUTER_API_KEY`와 별개로, 인증에 쓰이는 비밀 값(세션 시크릿 등)이 생기면 마찬가지로 `.env`에 두고 커밋하지 않는다.

## 성공 기준

- 회원가입 후 로그인한 사용자가 레시피를 저장하면, 로그아웃 후 다시 로그인해도 저장 목록이 그대로 남아있다.
- 사용자 A가 사용자 B의 저장 레시피를 볼 수 없다.

## 이전 단계와의 연계

이 단계는 1단계(재료 인식)와 2단계(레시피 생성) 위에서 동작하며, 이 두 단계의 출력 형식(재료 배열, 레시피 객체)을 그대로 재사용한다.
