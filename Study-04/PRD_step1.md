# PRD - 1단계: 냉장고 사진 재료 인식

## 개요

사용자가 업로드한 냉장고(또는 식재료) 사진에서 `google/gemma-4-26b-a4b-it:free` 모델을 이용해 보이는 식재료 목록을 인식한다. 이 단계는 전체 서비스의 입력부이며, 2단계(레시피 생성)의 입력 데이터를 만든다.

## 목표

- 사진 한 장을 업로드하면 그 안에 보이는 식재료 이름 목록을 얻는다.
- 인식 결과가 부정확할 수 있으므로, 사용자가 목록을 눈으로 확인하고 직접 추가/삭제/수정할 수 있게 한다.

## 사용자 스토리

- 사용자로서, 냉장고를 열어 찍은 사진을 올리면 그 안에 뭐가 있는지 자동으로 목록화되길 원한다.
- 사용자로서, 모델이 잘못 인식한 항목이 있으면 직접 지우거나 빠진 재료를 추가하고 싶다.

## 범위

**포함**
- 이미지 업로드 UI (jpg/png, 파일 크기 제한 예: 10MB 이하)
- 업로드된 이미지를 OpenRouter API(`google/gemma-4-26b-a4b-it:free`)로 전송해 재료 인식
- 인식된 재료를 구조화된 리스트(문자열 배열)로 파싱해 화면에 표시
- 사용자가 인식 결과를 수동으로 편집(추가/삭제/수정)
- API 실패(레이트리밋 429, 5xx 등) 시 에러 메시지와 재시도 유도

**제외 (다음 단계 이후)**
- 재료 목록을 이용한 레시피 생성 (2단계)
- 사용자 계정, 저장 기능 (3단계)

## 사용자 플로우

1. 사용자가 웹 화면에서 이미지 파일을 선택/업로드한다.
2. 프론트엔드가 이미지를 백엔드로 전송한다.
3. 백엔드가 이미지를 base64 또는 접근 가능한 URL 형태로 변환해 OpenRouter 모델을 호출한다.
4. 모델이 인식한 재료 목록을 텍스트(JSON)로 반환한다.
5. 백엔드가 이를 파싱해 재료 배열로 응답한다.
6. 프론트엔드가 편집 가능한 리스트(체크박스/태그 형태)로 표시한다.
7. 사용자가 목록을 확인/수정하고 "다음 단계로" 진행한다 (2단계 입력이 됨).

## 기능 요구사항

- 이미지 업로드는 파일 선택 또는 드래그앤드롭을 지원한다.
- 업로드 중/인식 중 로딩 상태를 표시한다.
- 모델 프롬프트는 식재료 이름만 JSON 배열로 반환하도록 유도한다. 예:
  ```
  이 사진에 보이는 식재료 이름만 한국어로 JSON 배열로 답해줘. 예: ["당근", "계란", "우유"]
  ```
- 모델 응답이 JSON 파싱에 실패하면(자유 텍스트로 응답한 경우), 줄바꿈/쉼표 기준으로 재료명을 추출하는 폴백 파서를 둔다.
- 인식된 재료가 0개인 경우 사용자에게 "재료를 인식하지 못했어요. 다시 시도하거나 직접 입력해주세요" 안내와 함께 수동 입력창을 제공한다.
- 재료 목록 수정 UI: 항목 삭제(x 버튼), 항목 추가(텍스트 입력 후 enter).

## API 설계 (초안)

```
POST /api/recognize-ingredients
Request: multipart/form-data { image: file }
Response 200: { "ingredients": ["당근", "계란", "우유"] }
Response 4xx/5xx: { "error": "message" }
```

## 비기능 요구사항

- OpenRouter 무료 모델 특성상 업스트림 429(rate limit)가 간헐적으로 발생할 수 있다. 서버 측에서 짧은 재시도(예: 최대 2회, 지수 백오프)를 수행하고, 그래도 실패하면 사용자에게 "잠시 후 다시 시도해주세요" 메시지를 반환한다.
- API 키(`OPENROUTER_API_KEY`)는 서버 환경변수로만 관리하며 프론트엔드에 노출하지 않는다.
- 이미지 자체는 서버에 영구 저장하지 않는다 (인식 목적으로만 사용, 요청 처리 후 폐기).

## 성공 기준

- 테스트용 냉장고 사진 여러 장에 대해, 사람이 봤을 때 사진에 실제로 있는 주요 재료의 대다수를 목록에 포함한다.
- 인식 실패/에러 상황에서도 사용자가 수동으로 재료를 입력해 다음 단계로 진행할 수 있다.
