# PRD - 2단계: 레시피 생성

## 개요

1단계에서 얻은 재료 목록을 입력으로 받아, `google/gemma-4-26b-a4b-it:free` 모델을 이용해 그 재료로 만들 수 있는 레시피를 추천한다.

## 목표

- 사용자가 가진 재료를 최대한 활용하는 레시피를 여러 개 제안한다.
- 각 레시피는 이름, 필요한 재료, 조리 순서를 포함해 실제로 따라 만들 수 있는 수준으로 제공한다.

## 사용자 스토리

- 사용자로서, 냉장고에 있는 재료로 오늘 뭘 해먹을 수 있는지 추천받고 싶다.
- 사용자로서, 여러 레시피 중 마음에 드는 것을 골라 자세한 조리법을 보고 싶다.

## 범위

**포함**
- 1단계에서 확정된 재료 목록을 받아 레시피 후보 생성 요청
- 레시피 후보 여러 개(예: 3개)를 카드 형태로 목록 표시 (이름 + 한 줄 설명)
- 레시피 카드를 선택하면 상세 화면(재료, 조리 순서, 예상 조리 시간)으로 이동
- API 실패/빈 응답에 대한 에러 처리 및 재시도 안내

**제외 (다음 단계 이후)**
- 레시피 저장, 사용자 프로필/선호도 반영 (3단계)

## 사용자 플로우

1. 사용자가 1단계에서 확정한 재료 목록을 가지고 "레시피 추천받기"를 누른다.
2. 백엔드가 재료 목록을 모델에 전달해 레시피 후보를 요청한다.
3. 모델이 레시피 후보들을 구조화된 형태(JSON)로 반환한다.
4. 프론트엔드가 후보 목록을 카드로 보여준다.
5. 사용자가 카드를 클릭하면 해당 레시피의 상세 조리법을 확인한다.

## 기능 요구사항

- 모델 프롬프트는 보유 재료 목록을 근거로, 각 레시피에 대해 아래 정보를 JSON으로 반환하도록 유도한다.
  - `title` (레시피 이름)
  - `used_ingredients` (보유 재료 중 사용하는 것)
  - `missing_ingredients` (추가로 필요한 재료, 없으면 빈 배열)
  - `steps` (조리 순서, 문자열 배열)
  - `estimated_time_minutes` (예상 조리 시간)
  - 예시 프롬프트:
    ```
    아래 재료로 만들 수 있는 요리 3개를 추천해줘. 각 요리는 title, used_ingredients,
    missing_ingredients, steps, estimated_time_minutes 필드를 가진 JSON 배열로만 답해줘.
    보유 재료: 당근, 계란, 우유
    ```
- 모델 응답 JSON 파싱 실패 시, 사용자에게 "레시피 생성에 실패했어요. 다시 시도해주세요" 메시지와 재시도 버튼을 제공한다.
- 보유 재료만으로 만들 수 있는 레시피가 없을 경우, `missing_ingredients`가 있는 레시피도 함께 제안하고 화면에서 "추가로 필요한 재료"를 눈에 띄게 표시한다.

## API 설계 (초안)

```
POST /api/recommend-recipes
Request: { "ingredients": ["당근", "계란", "우유"] }
Response 200: {
  "recipes": [
    {
      "title": "당근 계란 볶음밥",
      "used_ingredients": ["당근", "계란"],
      "missing_ingredients": ["밥"],
      "steps": ["당근을 잘게 썬다", "..."],
      "estimated_time_minutes": 15
    }
  ]
}
Response 4xx/5xx: { "error": "message" }
```

## 비기능 요구사항

- 1단계와 동일하게 무료 모델의 간헐적 429에 대비한 재시도 로직을 둔다.
- 레시피 생성 요청은 재료 목록이 비어있으면 호출하지 않고 프론트에서 먼저 검증한다.

## 성공 기준

- 추천된 레시피의 `used_ingredients`가 실제로 입력 재료 목록의 부분집합에 가깝다(모델이 엉뚱한 재료를 지어내지 않는지 정성적으로 확인).
- 사용자가 후보 중 하나를 선택해 끝까지 조리 순서를 볼 수 있다.
